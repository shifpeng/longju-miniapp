# 西引力.陇聚 一期 UI 设计任务书

更新：2026-09-21。状态：一期当前需求基线；Figma 原生稿已同步本轮更名和公告上移。

## 设计目标

设计工具必须使用 Figma，最终交付可编辑的页面、组件与可点击原型。服务在西安的甘肃老乡，兼顾年轻成员和中年成员的阅读、报名与操作体验。

一期功能范围：成员管理、老乡名录、活动与个人中心。商城属于二期，一期不放商品、购物车、优惠券或空商城入口。

整体方向为现代、简洁、有生活温度的社区。用清晰的信息层级、真实活动影像、适度留白和统一组件建立品质感。品牌名称沿用“西引力.陇聚”，未经确认不改字标或标点。

本项目是独立微信小程序，祖先目录的 Orca 桌面 IDE 风格指南描述的是另一产品。沿用其清晰层级、语义化变量、组件一致性和完整状态原则；本项目的移动端尺寸、品牌色和中文字体在 Figma 中单独建立规范，下面的视觉方向均为拟议方案。

## 视觉方向

- 浅色为一期主主题，以暖白背景、深色正文和低饱和中性色形成层次。
- 当前采用已确认的浅砂墨金主题：暖白浅砂背景、墨黑成员卡、古金与香槟金按钮；状态颜色独立定义。
- 人物与活动照片承担情感表达，地域线条或山形仅作轻量点缀，避免干扰文字阅读。
- 中文优先使用清晰的系统黑体；标题、正文、辅助信息建立明确字号层级，不用极小浅灰字表现高级感。
- 卡片圆角适度统一，用间距和细边界区分区块，阴影集中用于浮层。
- 图标采用同一套线性图标，导航始终带文字标签。
- 视觉稿只使用获准使用的照片；未取得实际素材时，用明确标注的占位素材，不虚构真实会员或活动记录。
- 约一万人的组织规模不等于已注册数量，页面上的“已加入人数”应使用实际系统数据。

## 核心页面布局

| 页面 | 从上到下的主要结构 | 首要操作 |
| --- | --- | --- |
| 首页 | 品牌与西安位置提示、欢迎语、单行公告、按身份展示的加入社群卡片、近期活动 | 游客申请加入；成员查看近期活动 |
| 老乡录 | 标题与搜索、家乡/西安区域/行业筛选、筛选结果摘要、成员列表 | 搜索或筛选老乡 |
| 活动列表 | 标题、活动分类与时间状态筛选、活动大图卡片 | 查看活动详情 |
| 我的 | 头像姓名与资格状态、我的报名、资料与隐私、帮助反馈 | 待审核者查看进度；成员管理报名 |
| 活动详情 | 封面、标题与状态、时间地点、组织者、活动介绍、报名说明、底部操作区 | 报名或查看已有报名 |
| 成员详情 | 头像姓名、家乡与行业、个人介绍、可提供的帮助、获准公开的联系方式 | 在对方允许时联系 |

首页顺序固定为：定位与欢迎语 → 单行公告 → 加入社群卡片 → 近期活动。公告沿用 44 px 轻量横幅，位于卡片上方；欢迎语保持在卡片外。公告为空时整栏隐藏并收起间距，一条时静态展示，多条时每 5 秒切换；点击进入对应详情，返回保留游客或待审核身份。四个底部入口固定为：首页、老乡录、活动、我的。

一期不增加「产品／商城／好物」底部入口，也不展示「暂未开放，敬请期待」占位页。二期保留产品模块规划，待商品或服务、履约与售后能力就绪后另行评审；不能仅换成「福利」等名称提前导入销售。详见 `community-phase-one.md`。

统一称为「老乡社群」，定位文案为「西安 · 甘肃老乡社群」，首页标题为「加入老乡社群」，按钮为「申请加入」。申请、审核、隐私、公告及活动组织者同步使用社群称谓；称谓调整不改变现有审核与权限规则。

老乡卡片信息控制在头像、姓名、家乡、西安区域、行业和简短介绍。批量筛选放在底部弹层中，显示已选项并支持清空。联系方式未公开时明确说明，不添加一期未实现的“申请联系”按钮。

活动卡片展示标题、日期、位置、报名状态和必要人数信息，状态文案不能仅依靠颜色区分。活动详情在关键报名信息之前不堆放长篇介绍。

## 首轮 Figma 页面与组件

文件页面建议组织为：

1. `00 · Design Brief`：范围、视觉方向、流程和设计说明。
2. `01 · Foundations`：颜色变量、字体样式、间距、圆角、图标、图片比例。
3. `02 · Components`：导航、按钮、输入框、标签、成员卡片、活动卡片、状态提示、底部弹层。
4. `03 · Mini Program`：四个主页面及详情、加入社群、报名和签到页面。
5. `04 · Prototype`：加入社群与活动两条可点击链路。
6. `05 · Admin`：管理后台概览、成员审核、活动与报名管理。
7. `06 · Handoff`：组件对应关系、字段、状态、资源与交互标注。

使用 Auto Layout、可复用组件和 Variants；颜色与字号引用变量/样式。文字保持可编辑，页面不能只放一张合成截图。

手机稿以一个常见设备宽度为主稿，再验证窄屏和宽屏、长姓名、长活动标题及较大字号。预留微信顶部导航与胶囊区域、底部安全区；固定报名按钮不能遮住内容。

先完成首页、老乡录、活动列表、我的、活动详情和加入社群申请的同一套视觉，再扩展其余页面与后台，保证设计语言连续。

## 必须覆盖的交互与状态

| 流程 | 需要设计的状态 |
| --- | --- |
| 加入社群 | 未登录、未申请、填写中、提交中、待审核、退回补充、通过、拒绝 |
| 老乡录 | 未审核无权限、加载中、有结果、无结果、请求失败、成员隐藏资料 |
| 报名 | 可报名、名额不足、报名截止、提交中、成功、已报名、取消、活动取消 |
| 同行人数 | 本人加同行人数说明、上限提示、提交时名额已变化 |
| 签到 | 未到签到时间、待签到、有效签到码、过期需刷新、已签到 |
| 编辑资料 | 必填校验、保存中、成功、失败后保留输入 |
| 后台审核 | 待处理、审核详情、通过、退回理由、无权限、处理冲突 |

原型链路一：首页 → 申请加入 → 提交 → 待审核 → 退回补充/审核通过。

原型链路二：活动列表 → 活动详情 → 确认人数与联系信息 → 报名成功 → 我的报名 → 签到码。

加载、错误、空状态有可执行的下一步。提交时立即防重复操作，失败保留已填资料。取消报名等操作在确认前写清人数及截止规则。

## 管理后台方向

后台与小程序共用品牌语义和基础样式，布局面向日常管理任务：左侧导航、顶部搜索/工具区、可筛选表格、详情页或抽屉。首屏优先展示待审核、近期活动和待处理反馈。

按 2026-09-22 已确认反馈，后台右侧内容区使用放大的沙漠驼队背景，内容卡片保持暖白底和轻微透底，保证表格与表单可读；具体稿件以 `admin-design-round-1.md` 和最新原生导出为准。成员电话遵循权限和脱敏规则，导出、停用成员等操作给出明确范围与反馈。高频筛选可直接操作，低频操作收进菜单。

## 评审与交付标准

- 评审以实际页面观感和可点击流程为依据，单独的风格文字或灵感图不能算最终设计交付。
- 主要操作清晰，普通中文正文易读，点击区域适合触控，选中与错误状态有文字或图标辅助。
- 每个页面使用一致的间距、图标、圆角与按钮规范；检查实际微信安全区。
- 用户界面不展示技术字段或虚构统计，不出现一期范围以外的可用功能入口。
- Figma 文件包含可编辑图层、组件、变量、核心状态、原型连线和开发标注。
- 交付实际 Figma 文件链接后，再据此进行页面实现与逐屏对照。
