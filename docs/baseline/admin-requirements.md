# 西引力.陇聚 · 一期管理后台需求

版本：2026-09-21 首轮。与小程序一期同步，统一使用「老乡社群」。本文件描述拟开发行为；设计中的数据、上传、扫码、登录和导出均为演示，不代表服务已经实现。

## 1. 目标与边界

面向社群工作人员的桌面网页后台，帮助管理员完成成员审核、活动组织和内容发布。首页优先呈现待办，不做商业经营大屏。

一期包含工作台、申请审核、成员档案、活动与报名签到、公告、活动回顾、反馈、管理员权限、导出记录和操作日志。不提供商品、商城、订单、支付、营销券或「敬请期待」菜单。商城继续留在二期需求。

后台独立管理员账号登录；小程序登录或成员资格不自动获得管理权。高权限账号第二因素验证沿用技术架构要求。首次账号由系统部署流程创建，不开放公众自助注册。

## 2. 导航与数据范围

| 分组 | 菜单 | 主要操作 |
| --- | --- | --- |
| 概览 | 工作台 | 查看待审核、待反馈、近期活动与待发布内容，进入具体任务 |
| 成员 | 申请审核 | 按状态筛选、查看资料、通过、退回补充、拒绝 |
| 成员 | 成员档案 | 搜索、查看资料与隐私、标签、内部备注、停用或恢复资格 |
| 活动 | 活动管理 | 新建、编辑、预览、发布、取消；进入报名、签到与回顾 |
| 内容 | 社群公告 | 草稿、展示时间与排序、预览、发布、撤下 |
| 内容 | 活动回顾 | 已结束活动图文、相册、封面、草稿及发布版本 |
| 服务 | 意见反馈 | 查看、处理、回复与关闭；原举报需求按反馈类型管理 |
| 系统 | 管理员与权限 | 账号、角色、数据范围、停用与会话撤销 |
| 系统 | 导出记录 | 查看本人有权导出的任务、下载结果、失败重试与过期提示 |
| 系统 | 操作日志 | 按操作者、动作、对象、结果、时间查询关键操作 |

活动的「报名 / 签到 / 回顾」是活动上下文内的操作，必须持续显示活动名称。顶栏显示当前管理角色与数据范围；切换账号或权限变化后清理无权访问的数据。无权菜单不显示，直接访问链接时仍需后端校验并显示无权限页。

## 3. 角色与权限

| 能力 | 成员管理员 | 活动运营 | 超级管理员 |
| --- | --- | --- | --- |
| 申请审核、成员档案 | 授权范围内可管理 | 仅活动所需的已报名成员摘要 | 全部 |
| 活动、报名、签到、回顾 | 默认不可管理 | 分配活动内可管理 | 全部 |
| 公告、反馈 | 按额外权限授权 | 按额外权限授权 | 全部 |
| 管理员与角色配置 | 不可 | 不可 | 可 |
| 查看完整电话 | 单独授权且限审核用途 | 单独授权且限已报名活动联系用途 | 仍需明确用途并记录 |
| 导出 | 独立授权，限数据范围 | 独立授权，限数据范围 | 独立授权 |
| 操作日志 | 默认不可 | 默认不可 | 可查询 |

分组负责人作为已有角色叠加家乡/区域或分配活动的数据范围，不新增无边界的「负责人超级权限」。默认角色不可越权授权，不能移除最后一位有效超级管理员；角色撤销和账号停用后已有会话及时失效。

首轮画稿以拥有所示权限的演示管理员展示导航全貌；无权限状态另有画板，不代表每个管理员都能看到所有入口。生产角色配置以这张权限表为基线。

## 4. 工作台

指标为当前授权范围内的实时业务结果：有效成员数、待审核数、活动数、待处理反馈数。空数据为 0，加载中显示骨架；请求失败显示重试，不能把失败伪装成 0。每张待办卡可进入相应列表并带上筛选条件。

待办按紧急程度显示待审核申请、即将开始活动、未发布回顾；任务为零时显示「当前暂无待办」。近期活动显示日期、地点、报名人数（含同行）与状态，不混用报名记录数和参与人数。

## 5. 申请审核与成员档案

申请列表：姓名、脱敏电话、家乡、现居区域、行业、申请时间、状态、操作。筛选支持关键词、状态、家乡/区域、申请日期；保留用户查询条件和页码，重置恢复默认。页大小默认 20，可选 50；总数来自服务端。

详情包含申请资料快照、资料补充历史、审核历史、对申请人可见的审核说明、仅管理员可见的内部备注。电话默认脱敏，授权查看需明确业务用途并记录。管理员不能替申请人悄悄改变姓名、电话或隐私设置。

| 当前状态 | 操作与校验 | 成员端结果 |
| --- | --- | --- |
| 待审核 | 通过：确认对象，提交一次；无需必填理由 | 申请通过，成员资格生效 |
| 待审核 | 退回补充：必须填写具体待补充项 | 显示原因、保留资料、允许修改后重新提交 |
| 待审核 | 拒绝：必须填写说明 | 显示未通过与说明，提供帮助入口 |
| 需补充 | 申请人重新提交后才再次进入待审核 | 保留既往历史 |
| 已处理 | 不再次显示可提交的审核按钮 | 显示最新结论 |

一期不提供批量通过或批量拒绝。提交时禁用重复操作；失败保留填写内容。多人同时审核时校验版本，落后提交显示「已由其他管理员处理」，展示最新状态，不覆盖他人的结论。

成员档案展示有效/停用/已退出资格，标签与内部备注可独立编辑。资格和申请状态分开：通过是历史审核结论，停用是当前资格。停用必须填写原因并确认，阻止访问名录和新报名；历史报名及签到保留，是否取消某场报名需进入该活动按规则单独处理。恢复资格需权限、说明和审计。退出/注销按架构规则处理，不在列表提供永久删除真实成员的快捷按钮。

## 6. 活动、报名与签到

活动列表支持草稿、未开始、进行中、已结束、已取消，并单独展示报名中/已截止；生命周期、报名状态和发布状态不得混为一个枚举。字段：活动名称、起止时间、地点、发布状态、参加人数/名额、报名记录数、负责人、操作。

编辑字段：标题（必填，1–60 字）、摘要（选填，≤120 字）、封面、开始/结束时间、详细地点、介绍、活动负责人、活动可见范围、报名资格、报名开始/截止、取消截止、人数上限、同行上限。一期沿用最多 2 位同行；本人及同行均占名额，已审核成员可报名，活动展示可配置公开或仅成员。

发布时间与报名窗口独立；报名开始 < 报名截止 ≤ 活动开始 < 活动结束，取消截止 ≤ 活动开始。人数上限为正整数且不得低于当前有效占用人数。时间输入明确为北京时间。校验失败定位字段并保留内容。保存草稿不发布；发布前预览小程序展示并确认。

已发布活动修改关键时间、地点或人数规则需展示变更摘要、校验已有报名并留痕。不能通过普通编辑重开已结束活动。取消活动必须写原因并二次确认；停止报名并将有效报名标记活动取消，通知结果以小程序状态为准，订阅消息不承诺必达。

报名表格显示报名人、脱敏联系电话、同行人数、总人数、报名状态、报名时间、签到状态。示例「本人 1 + 同行 1 = 2 人」；顶部明确 18 份有效报名/26 位参加者。取消释放名额只能执行一次，签到后不支持普通取消。管理员取消需原因和权限，截止规则或特殊处理由服务端核验。

签到工作区先选定活动，扫码后显示活动、报名人及包含同行的总人数，经确认后核销本次报名；一期核销以整份报名为单位，不记录逐位同行单独签到。重复码返回已签到时间与操作者，不二次计数。错活动、码过期、活动未到签到时间、报名取消、无权限均给出清晰原因。无设备权限时可改用授权的人工查询补签，不能只凭姓名直接核销；补签须核对报名和填写原因，记录操作者。

桌面后台支持摄像头或扫码枪录入，现场小屏核销为同一网页的简化操作模式；本轮桌面稿不等于已验证移动端摄像头兼容性。

## 7. 公告与活动回顾

公告字段：标题（必填，1–40 字）、正文（必填）、可见范围、展示开始/结束、排序值、状态。首页轮播只取当前有效且有权查看的已发布公告；排序值越小越靠前，同值按发布时间倒序。无结束时间表示持续展示。保存草稿不影响已发布版本；发布或更新成功后整体生效。撤下需要确认，小程序不再显示，历史及草稿保留。到期仅退出首页展示，不自动删除正文；无权查看或已撤下的直接链接展示不可用。

公告预览须包含首页单行截断效果及详情全文。展示位置固定在欢迎语之后、加入社群卡片之前；继续沿用 5 秒轮播和来源首页返回规则。

活动回顾字段和发布事务以 [活动回顾需求](activity-recap.md) 为准：仅已结束活动可发布，最多 30 张、每张 ≤10 MB、JPEG/PNG/WebP；逐张进度、失败重试、移除、排序、封面、图片说明、纯文字/纯照片场景。上传中/处理失败图片需修复或移除才可发布。保存草稿与已发布版本隔离；撤下回到「精彩回顾整理中」，不改变报名与签到。不可扩大原活动可见范围。多人冲突保留本地草稿。

## 8. 反馈、权限、导出与日志

反馈含类型（建议/问题/举报）、内容、关联对象、提交人、联系授权、时间、处理状态、处理人。待处理 → 处理中 → 已解决/已关闭；首次认领和提交结论校验版本。处理备注仅内部可见，对用户回复须明确区分并预览确认，不自动承诺站外消息。举报相关个人信息仅授权处理人可见。无联系授权不展示可直接联系操作。

权限页包含管理员列表、角色、数据范围、账号状态和最近登录；创建/调整角色要展示将获得及失去的能力。停用他人账号二次确认，不允许停用最后一个有效超级管理员；修改自身权限需重新鉴权。审计记录操作者、时间、对象、动作、结果及必要脱敏变更摘要。

导出在用户明确点击后创建异步任务，确认数据范围、筛选条件、预计记录数和字段；电话默认脱敏，导出完整电话须额外权限并填写用途。状态为排队/生成中/可下载/失败/已过期。建议下载有效期 24 小时，上线时可配置；每次下载重新鉴权，权限撤销后不可访问历史文件。失败可重试同一筛选快照；大数据不使用当前页冒充全量，文件记录生成时间与口径。日志不展示完整电话或凭据。

## 9. 通用交互与状态

桌面主稿 1440 × 1000，内容区滚动，导航与页头固定。1024 px 起侧栏收为图标栏，较宽数据表在自身容器内横向滚动；不压缩到难以阅读。小屏优先保障签到，不承诺全部后台表单移动适配。

表单有必填、错误、保存中、成功、失败后保留、未保存离开确认；危险操作显示对象与后果。抽屉或确认页可返回来源列表并保留筛选。加载、无结果、无权限、登录过期、版本冲突均有明确下一步。登录过期不在 URL 中保存敏感表单内容；重新登录后按权限恢复可安全恢复的操作。

视觉复用浅砂、暖白、墨色和青绿状态色。按 2026-09-22 反馈，右侧内容区使用放大的低对比度沙漠驼队背景，主内容卡片保持暖白色和轻微透底，确保文字可读。主操作为墨色实底，危险操作与普通取消区分。正文 14 px，辅助说明 12 px，标题 22/25 px；导航与表格状态均有文字标签。

## 10. 首轮设计覆盖与验收

首轮交付工作台、申请列表、审核详情、成员档案、活动列表、活动编辑、报名管理、签到、公告列表/编辑、回顾编辑、反馈、管理员权限、导出记录、操作日志、登录，以及审核退回/拒绝/成功/冲突、发布预览/成功、签到异常、通用空/加载/失败/无权限等关键预设状态。Figma 数据与表单为可点击示例，真实输入和后端事务按上述需求实施。

验收主链路：工作台 → 申请审核 → 详情 → 通过/退回/拒绝；活动列表 → 编辑 → 发布预览 → 发布成功 → 报名 → 签到；公告列表 → 编辑 → 预览 → 发布；已结束活动 → 回顾编辑 → 图片处理 → 发布；导出确认 → 生成中 → 下载列表；管理员权限 → 调整确认 → 保存。

业务验收另需真实接口验证：无越权、无重复审核、无报名超员、无重复签到、导出数据范围正确、草稿不污染线上、发布失败不替换线上版本。Figma 布局和链接检查不替代这些开发测试。

原稿节点、画板数量与实际验收结果记录在 `admin-design-round-1.md`，以实际执行后记录为准。
