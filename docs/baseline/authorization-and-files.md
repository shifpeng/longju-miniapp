# 一期权限、文件与后台任务

版本：2026-09-22，开发设计基线。数据字段见 [数据模型](data-model-and-transactions.md)，接口见 [接口契约](api-contracts.md)。

## 1. 权限判断

每次请求按“主体有效 → 动作已授权 → 对象在范围内 → 字段允许访问”判断。前端隐藏菜单只改善操作体验，不能替代后端检查。后台没有自动绕过检查的超级管理员通道。

角色提供动作模板；`role_binding` 为管理员分配角色，`binding_scope` 按业务域附加范围。完整电话、导出和人工补签等额外能力可用 `admin_permission_grant` 单独授权。任一授权都必须有正确业务域的范围，无范围默认拒绝。角色模板变更与个人授权变更都递增受影响管理员 `auth_epoch`，撤销其现有会话。

### 范围模型

| 类型 | 解释 | 可用对象 |
| --- | --- | --- |
| GLOBAL | 该业务域全量数据 | 需明确配置；不自动覆盖其他业务域 |
| MEMBER_REGION | 家乡集合与现居区域集合 | 申请、成员、成员反馈 |
| ACTIVITY_SET | 指定 activity_id 集合 | 活动、该活动报名/签到/回顾与相关反馈 |
| SELF | 当前主体自己的资源 | 普通成员资料/报名/反馈；管理员自己的导出任务 |

MEMBER_REGION 同一规则内，不同维度取交集、同维度多个值取并集；空维度表示该维度不限制，但两个维度都空无效，不能借此变成 GLOBAL。多个规则/授权取并集，但只能合并同一动作的范围，不能将角色 A 的动作配上角色 B 的更大范围。最终敏感操作范围还要与基础查询权限范围取交集。

业务域代码固定为 MEMBERSHIP、ACTIVITY、ANNOUNCEMENT、FEEDBACK、ADMINISTRATION、AUDIT。成员权限及成员导出属于 MEMBERSHIP，报名/签到/回顾与报名导出属于 ACTIVITY；公告、反馈、管理员配置、审计分别归属其同名域。MEMBER_REGION 仅用于 MEMBERSHIP/FEEDBACK，ACTIVITY_SET 仅用于 ACTIVITY/FEEDBACK。SELF 是接口固有的本人资源策略，不允许后台把管理员身份映射为任意成员来配置该范围。

例如：拥有“雁塔区成员查询”和“全部成员导出”也只能导出雁塔区成员；不能因另一活动运营角色拥有活动 A 就获得活动 A 报名人的完整成员档案。

审核范围取当前提交修订的不可变家乡/现居快照；重提改变范围后，旧管理员不可继续处理。成员档案范围取当前有效资料。名单查询、单条详情、总数、工作台指标、电话查看和导出共用同一个范围构造器，数据库先过滤再分页/统计。对象不在范围内的详情统一返回 404；缺少动作权限返回 403，不返回越权记录存在性。

### 动作矩阵

| 动作组/权限代码 | 成员管理员默认 | 活动运营默认 | 超级管理员默认 | 附加要求 |
| --- | --- | --- | --- | --- |
| `application.read/review` | 指定成员范围 | 无 | GLOBAL | 审核绑定申请快照 |
| `member.read/update_note/manage_qualification` | 指定成员范围 | 无 | GLOBAL | 不能替成员修改本人填写的资料与隐私 |
| `activity.create` | 无 | 可创建 | 可创建 | 创建人与指定负责人必须是有效管理员，非超级管理员只能指定自己 |
| `activity.read/edit/publish/cancel` | 无 | 分配活动 | GLOBAL | 新建活动同事务把创建者加入授权集合，不能据此访问其他活动 |
| `registration.read/cancel`、`checkin.scan`、`recap.read/edit/publish` | 无 | 分配活动 | GLOBAL | 报名人只提供本活动必要摘要 |
| `announcement.read/edit/publish`、`feedback.read/process` | 无 | 无 | GLOBAL | 可对其他角色单独授予对应业务域范围 |
| `member.phone.reveal`、`registration.phone.reveal` | 无 | 无 | 可查看，仍填写用途 | 与对应基础读取范围相交，审计每次查看 |
| `checkin.manual` | 无 | 单独授予 | GLOBAL | 报名ID、核对方式、原因 |
| `export.members`、`export.registrations`、`export.full_phone` | 无 | 无 | 无 | 超级管理员也要显式授权；full_phone 必须同时具备对应 phone.reveal |
| `admin.manage`、`audit.read` | 无 | 无 | GLOBAL | 自身变更与敏感授权需要近期第二因素验证 |

`activity.create` 的授予与新活动自分配在同一事务，属于限定创建能力；给他人分配活动范围仍要求 `admin.manage`。既有角色模板在迁移中定义，不向业务管理员开放任意 SQL 条件或表达式配置。

### 字段与个人数据

- 成员名录只返回资格 ACTIVE 且 directory_visible 的成员。详情重新检查资格和可见性；电话仅在目标成员允许公开时，向有名录资格的当前成员提供。无公开许可不返回电话号码字段。
- 后台列表只返回 `phoneMasked`。完整电话通过专门 POST 接口，传业务用途，服务器记录审计后返回，响应 `Cache-Control: no-store`。界面关闭详情或退出时清理。
- 活动联系人使用报名快照，不随成员资料变化改写。成员端本人可以读取自己的联系信息；运营端仍受活动范围与电话权限约束。
- 内部备注、举报信息与对外回复采用分开的 DTO，禁止将持久化对象直接序列化到成员端。反馈联系操作还要求提交时 contact_consent 为真。
- 照片说明、富文本、文件名和所有列表检索值按普通数据处理；服务端做长度限制、允许列表过滤和参数化 SQL。

## 2. 权限变更的原子性

管理员创建、激活、停用、角色/范围修改、第二因素恢复均先排他锁定 `security_guard`，再读取当前有效超级管理员数量与目标状态，完成更新和审计后提交。有效超级管理员必须账号 ACTIVE、角色 SUPER_ADMIN 有效且第二因素已绑定；INVITED 账号不计数。若结果为零则整笔操作拒绝。

关键业务写入和完整电话读取在事务中对同一 guard 取共享锁，并读取当前授权再操作；授权撤销在这些请求提交前等待，提交后新请求立即按新权限执行。正常查询也实时检查 auth_epoch 与范围；不以进程内缓存作为授权事实。范围变更清理当前前端数据并返回重新登录状态。

管理员修改自己的权限、完整电话导出授权、恢复他人第二因素时要求近 5 分钟的第二因素验证。普通角色没有转授权能力；一期仅 GLOBAL 的 admin.manage 可配置预置动作与范围，授权能力与本人实际读取/导出能力分开。SUPER_ADMIN 授予自身导出仍必须走明确、审计的授权操作，不能靠角色通配符自动获得；具备有限范围的角色不会因附加一个范围绑定而获得全域转授权能力。

## 3. 文件上传与处理

一期文件桶全部私有。品牌沙漠等固定静态资源作为应用构建资产独立发布，用户图片和导出文件不混用该公开目录。

1. 后台申请上传授权，提交用途、所属活动/内容、声明类型、字节数。服务端校验编辑权限，创建 `media_asset`，生成固定的随机对象键。
2. 采用限时 10 分钟、限定单个对象键的上传凭证；优先用支持大小/类型策略的签名表单。存储实现不支持可靠大小限制时改走服务端限流上传，不发无限制桶凭证。上传阶段没有读取权限，不能列桶或覆盖别的对象。
3. 上传完成调用 complete；服务端读取对象元数据并验证实际字节数，后台任务验证 magic bytes 和完整解码。声明 Content-Type 或扩展名不能替代验证。
4. 图片任务限制 40MP 解码像素和内存/执行时间，剥离 EXIF（含位置），按方向重编码，生成最长边 480px 缩略图和 1920px 展示大图、不放大小图。原图留在私有区，成员只访问处理后版本。
5. 全部必要变体成功后才标 READY；发布只接受当前上下文可引用且 READY 的资产。故障返回可重试原因，原文件未变时可重试处理；换文件必须创建新资产。

回顾限制为最多 30 张，每张 ≤10MiB，允许 JPEG/PNG/WebP；一期拒绝动画与 SVG。服务端也约束草稿槽位和并行上传数量，不能靠前端计数保证最多 30 张。活动封面、头像复用验证流程，头像限制 5MiB；所有大小在界面明确展示。

状态：PENDING_UPLOAD → UPLOADED → PROCESSING → READY；校验/处理失败为 FAILED，可重试的失败重回 PROCESSING；过期未完成为 EXPIRED；无引用且到期为 DELETING → DELETED。READY 文件不可原地覆写。上传凭证过期后才能确认并固定源文件版本，或先将源对象复制到不可覆盖的处理键再校验；确保 complete 后重复使用旧上传凭证不会改变已验证内容。

## 4. 图片访问与微信相册

图片 URL 由服务端为具体展示上下文签发，不能提交任意 asset_id 换取文件。上下文包括已发布公告/回顾版本、当前成员头像或有编辑权限的草稿。正文响应只包含有权读取的媒体 ID 与处理后尺寸。

- 小程序先用 Bearer 会话批量申请媒体访问票据，默认有效期 5 分钟；票据绑定主体、上下文、媒体和变体，URL 指向业务媒体网关。
- 网关每次请求都重新校验票据、账号状态、当前成员资格、内容是否仍已发布、范围以及图片是否仍属于可访问版本，然后由服务器读取私有存储并返回字节，**不重定向到对象存储签名地址**。
- 这使 `<image>` 与 `wx.previewImage` 的 URL 无需携带自定义 Authorization 头，也能在内容撤下或权限撤销后拒绝新的请求。请求日志删去 ticket 参数，Referer 不作为授权凭据。
- 私有图片及上下文票据响应使用 `Cache-Control: private, no-store`，不经共享 CDN 缓存；公开活动图片也需经上下文检查，先不加入会妨碍撤下的 CDN 缓存。
- 打开完整相册时按发布顺序一次取得最多 30 个展示链接，刷新后顺序与当前照片 ID 一致。票据过期重新授权；原生预览遇到过期下载失败时，返回相册可重新打开。iOS/Android 的预加载、失败提示与大图内存占用在真机联调验证。
- 已完成下载、已显示的图片无法从他人设备远程追回；撤下保证后续新请求不可读取，不声称清除既有客户端副本。

活动范围收紧时，回顾图片采用当前活动范围与发布快照范围的交集。旧发布版本的图片只允许具有历史版本查看权的管理员读取，成员不能通过旧 URL 遍历历史照片。

## 5. 导出生成与下载

### 创建与生成

导出类型一期限定成员与指定活动报名；所有请求必须明确类型、筛选、字段及是否含完整电话，禁止客户端指定 SQL 或对象存储键。`export.full_phone`、相应 phone.reveal、基本数据读取、相应 export 权限必须同时满足，完整电话还要求用途与近期第二因素。

创建时存储操作者、过滤条件、字段口径、规范化范围与 auth_epoch。预计记录数仅作提示；实际数量以生成结果为准。默认最大 50,000 行，超出提示缩小条件，不能悄悄截断成部分数据。

工作线程开始和发布结果时都重查授权。读取使用专用短生命周期 REPEATABLE READ 一致性快照，分批读取全部结果并建立私有资源清单；生成时间记为 snapshot_at。文件是生成时快照，重试沿用筛选/字段条件，但读取重试时的数据，界面和文件标注新的生成时间。结果为 XLSX，所有用户输入用显式文本单元格，不写公式、宏或可执行链接。

生成过程不持有写锁等待网络或对象存储。结果写入每次尝试独立的随机键；校验 owner 的 auth_epoch、当前记录范围、任务租约代次仍有效后，才把任务置 READY。权限变化或清单中资源已超范围，则作废结果并要求重新发起，不能继续沿用旧权限范围。

### 下载

下载使用同源 `/api/v1/admin/exports/{id}/file`，由服务器验证管理员 Cookie、会话、任务所有者、导出及字段权限、当前范围和有效期后传输文件；不发可直接下载存储文件的签名 URL。只允许任务创建者下载，超级管理员可查看必要审计记录但不能借任务 ID 下载别人的文件。

下载前用资源清单再检查当前范围及关联用户 privacy_epoch。例如成员已搬出负责区域，即使管理员角色没变，也不能继续下载含该成员的旧文件；用户已申请注销/删除资料时，旧含个人信息快照同样不可下载，GLOBAL 管理员也不例外。任务标记结果失效并提示重新生成。auth_epoch 改变时保守作废旧导出，包括权限扩大后的旧任务。

文件响应使用 attachment、固定安全文件名、`Cache-Control: no-store`、`X-Content-Type-Options: nosniff`；每个新请求（包括 Range）重新鉴权，记录下载开始及结束结果。权限撤销后拒绝新下载请求；已经开始传输的字节无法收回，下载流分块时检查权限版本变化并中止余下传输，不为长下载持有数据库事务。

任务状态：QUEUED → RUNNING → READY / FAILED；READY → EXPIRED。有效期默认生成后 24 小时，与任何访问票据无关。因授权变化失败不能自动重试旧任务；普通失败重试保留任务 ID、attempt + 1 和原筛选条件，但重新检查当前授权。过期文件清理后保留脱敏任务与审计。

## 6. 后台任务、清理与保留

后台任务使用 MySQL 持久队列，不引入外部消息队列。业务变更与任务创建在同一事务，任务唯一键避免重复入队；工作线程用 `FOR UPDATE SKIP LOCKED` 领取，处理在事务外，租约 60 秒、每 20 秒续租，提交结果必须比较 lease_generation 与当前任务状态。旧工作线程即使迟到也不能替换新结果。

暂定图片处理并发 1、导出并发 1；失败按 30 秒/2 分钟/10 分钟重试，最多 3 次自动重试，之后进入人工可重试状态。媒体类型/大小不合法、权限撤销等不可重试错误直接终止。清理任务可重复执行，删除不存在的文件视为成功。

回收流程先锁资产并确认引用为零，将其标 DELETING，提交后删对象；创建新引用也需锁资产且只允许 READY，避免检查后又被发布引用。对象删除失败保留状态等待重试，不把未删完资产误标完成。

| 数据 | 一期工程保留默认值 | 清理约束 |
| --- | --- | --- |
| 未完成上传 | 授权到期后 24 小时 | 无内容引用才清理 |
| 已上传但没有任何草稿/发布/历史引用的图片 | 7 天 | 包含未完成的孤立尝试文件 |
| 内容草稿 | 主动删除前保留 | 不能按最后编辑时间自动删仍被使用的草稿 |
| 被替换的历史发布版本及引用 | 180 天 | 当前线上版不受此上限；个人删除请求另行处理 |
| 导出文件及资源清单 | 生成后 24 小时 | 到期立即禁止下载，物理删除允许任务重试 |
| 登录会话/挑战/媒体票据 | 到期后每日清理 | 立即拒绝已到期凭据，不等待清理 |
| 幂等结果 | 7 天 | 不含完整敏感响应 |
| 应用普通日志 | 30 天 | 不含密钥、电话、正文与票据 |
| 管理审计、审核与资格历史 | 180 天起的配置保留策略 | 注销后仅保留不可直接识别的必要事件，不保留电话与自由文本身份信息 |
| 数据库备份/PITR | 30 天 / 至少 7 天日志窗口 | 恢复后先重放注销与撤权清单再开放服务 |

这些是用于实现清理任务的工程默认值，不作为已经对外发布的隐私承诺；上线前由实际隐私说明约束最终参数。账号注销进入 CLOSING 后立即禁止访问，在线个人资料目标 7 天内完成清理并告警超期；关联自由文本/照片应进入明确的逐项处理队列，未完成不能宣称注销清理完成。备份不逐条改写，到期淘汰；独立加密保留近期注销清单，恢复时用于防止被清理资料重新上线，清单到最后相关备份到期后删除。

## 7. 验收场景

实现阶段以真实接口验证：不同区域管理员互访、从列表切换到直接详情、越权统计与导出、电话用途审计、两位超级管理员并发互相停用、任务执行期间撤权、生成后成员迁出范围、下载流期间撤权、发布与清理同一图片竞争、旧工作线程在租约失效后提交、撤下内容后复用媒体链接。现阶段仅完成设计，没有执行服务端验收。
