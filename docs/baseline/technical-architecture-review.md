## 本轮一致性核对

- 对照小程序一期、后台需求与活动回顾规则，覆盖申请、成员、活动、报名、签到、公告、回顾、反馈、权限、导出和审计。
- 活动发布状态、生命周期、报名窗口分别表达；人数区分报名份数、含同行参加人数与签到人数。
- 成员资格停用/退出保留既有报名，账号禁用/注销另行处理；普通成员不能通过旧申请 APPROVED 结果绕过当前资格。
- 审核使用当前提交修订的资料快照；成员范围使用当前资料；导出时保存条件、生成时建立数据快照、下载时重新检查权限和范围。
- 数据模型与契约对齐 version、If-Match、Idempotency-Key、expectedGeneration 和签到 generation；旧请求不能复活取消后的业务状态。
- 内容草稿与线上版本分离；照片清理不能删除仍被发布引用的文件；角色、任务租约及媒体访问都以数据库事实为准。
- 新增文件之间的本地链接和 Markdown 代码块完整性检查通过。此项是文档检查，不是业务自动化测试。
- 本轮读取微信官方登录、网络、图片预览页面，以及 Spring Boot、MyBatis、Vite 官方环境要求。基准为 Java21、Boot4.1.1、MyBatis Starter4.0.0、MySQL8.4；没有把官方兼容矩阵当成实际构建结果。

## 已明确的默认值

现有需求未给出而实现必须有值的技术参数，已经由本轮设计提供默认值：普通成员会话7天，后台会话绝对8小时/空闲30分钟；签到从活动开始前30分钟到结束，签到码120秒；导出生成后24小时过期；私有媒体访问票据5分钟且逐次鉴权；并发版本/幂等结果、任务租约和重试规则均已写明。

这些参数在服务端集中配置并返回前端，不能由两个前端各自硬编码。其业务后果已在状态和接口设计中列出，实施时按此基线执行；如后续运营提出不同规则，再通过明确变更调整，无需用户现在逐项作技术选择。
