## 用户已确定的范围

品牌为「西引力.陇聚」，定位服务在西安的甘肃老乡，对外称「老乡社群」、操作称「申请加入」。一期小程序底部只有首页、老乡录、活动、我的；商城/产品、支付、退款属于二期，一期不放占位入口。

小程序、后管分别构建发布，共用模块化单体后端。三个仓库独立维护依赖与锁文件，不引入 monorepo/workspace、Git 子模块或跨仓源码导入。服务端维护和发布唯一 OpenAPI 契约，客户端按具体版本使用。

UI 稿是视觉和行为输入，示例成员、手机号、活动、统计与预设跳转不是正式业务数据。小程序 68 张、后台 188 张为主页面与状态画板数量，不意味着要创建同等数量的静态业务页面。

独立 session 只负责当前仓库，其他仓库可读取契约和参考文档；跨仓库改动需属于该 session 的用户任务范围，不能替另一会话覆盖代码。发现新规则冲突时先查当前需求与架构，技术实施细节由开发者解决；只有真正改变业务范围、费用或发布安排的事项才交用户决定。

## 核心约束

- 登录身份、申请审核结论、当前成员资格、管理权限分开；成员停用/退出保留历史报名，不能凭旧 APPROVED 状态绕过资格检查。
- 本人加最多 2 位同行均占名额；服务端统一计算人数与窗口；报名、取消、签到按定义锁序，取消后重报增加 generation，旧码失效。
- 公告与回顾草稿不改变线上内容，发布成功后原子替换；撤下后新详情/媒体请求不可访问。
- 区域/活动范围在服务端执行，电话和导出独立授权；导出经实时鉴权网关下载，不能发绕过撤权的直连存储 URL。
- 原型不等于运行系统；本地 Node 设计检查、Figma 原生验收和真实业务测试分别报告，不能混称通过。
- 默认不修改 Figma 原稿。前端按已确认设计实现；需要改变设计时先判断是否属于用户当前要求。
