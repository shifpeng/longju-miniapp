# 一期身份接入、工程与交付

版本：2026-09-22，开发设计基线。本文确定方案及实施阶段；实际账号、云服务采购、部署和应用编码尚未执行。

## 1. 微信登录与会话

客户端调用 `wx.login` 获取 code，服务端使用环境中的 appid/secret 调用 `auth.code2Session`，只信任服务端换取的 appid + openid。唯一键竞争由数据库约束处理；同一微信身份不会创建两个账号。微信 code 一次性使用，交换失败或客户端丢失登录结果时重新获取 code；不能将 code 当长期会话。

内部令牌使用密码学安全随机源生成 32 字节，客户端持有原值，数据库仅保存 SHA-256 摘要。小程序通过 Authorization Bearer 发送，默认绝对有效期 7 天；过期重新微信登录，没有额外长期 refresh token。登录不自动获得成员资格。账号禁用、注销及 auth_epoch 变化使已有令牌立即失效。

微信 session_key 不下发、不写日志；一期没有需要解密微信数据的流程，不持久保存它。unionid 不是必须字段，不以缺少 unionid 阻止登录。联系电话按现有申请稿手工填写，标 `MANUAL` 与未验证，仅用于审核和已报名活动联系，不用作登录身份或恢复凭据；一期不主动接入短信付费服务或手机号快捷获取。

小程序只持久化自身会话和非敏感偏好；退出删除会话及私有页面缓存，切换身份重新加载资料。无令牌可浏览公开公告与活动；提交了失效令牌的请求返回 401，不静默当游客返回一份形似成功的结果。

## 2. 管理员账号与第二因素

管理员账号独立于成员账号。密码采用成熟实现的 Argon2id，初始参数 64MiB / 3 次迭代 / 并行度1，每个密码随机盐；构建和部署时测量验证耗时并限制并发，目标在常规请求可接受范围，不手写密码算法。密码允许 12–128 字符及密码管理器生成值，拒绝明显常见密码，不设置默认共享密码。

一期第二因素选 **TOTP 身份验证器**，避免引入短信平台和短信费用。SUPER_ADMIN、管理员授权管理、查看完整电话或导出完整电话的账号必须绑定；其他账号可选绑定。授予这些权限时若未绑定，返回必须完成绑定的状态并撤销旧会话，不能在未完成第二因素时开放高权限。

TOTP 采用标准 RFC 6238、6位、30秒步长，允许前后一个步长校时误差，服务器同步时间。密钥用独立加密密钥保护；记录 last_used_step 并原子比较，已用于验证的时间步不得重放。登录挑战 5 分钟、最多 5 次尝试，挑战绑定当前浏览器预会话，不能跨挑战兑换完整会话。

首次绑定展示一次性 otpauth 二维码并要求输入动态码验证；之后不再展示密钥。生成 8 个随机恢复码，只展示一次，数据库保存摘要并记录是否使用。绑定材料、动态码、恢复码和激活凭证禁止进入 URL 查询、日志与幂等响应缓存。

### 创建与恢复

1. 首位超级管理员由部署时的一次性引导流程建立 INVITED 记录；操作者在受控环境获得短期激活凭证，设置密码、绑定并验证 TOTP 后才置 ACTIVE。引导只在尚无管理员时可执行，完成后关闭，不暴露公共注册接口。
2. 后续账号由拥有 admin.manage 的管理员创建 INVITED，激活凭证 24 小时有效且仅使用一次。管理者自行交接该凭证；系统不假定已接入邮件、短信或站外自动消息。凭证进入页面后由 POST 提交，页面不加载第三方资源。
3. 忘记第二因素可用密码 + 单次恢复码进入仅能重绑的恢复会话；完成新 TOTP 后撤销旧密钥与全部会话。恢复过程不直接授予访问管理数据的权限。
4. 忘记密码且存在其他超级管理员时，由后者近期 TOTP 验证并填写原因创建一次性恢复激活凭证，撤销目标原会话；不能读出或替目标设置原密码。
5. 唯一超级管理员丢失全部凭据时，使用受控部署维护命令恢复：需主机/密钥维护权限、维护记录、一次性本机恢复挑战，新密码与新 TOTP 验证后在单一事务中替换并撤销旧会话。不是公网“万能密码”接口；正常业务 API 仍禁止移除最后一位有效超级管理员。

普通管理员的密码重新验证用于敏感操作；高权限操作必须 TOTP 近期验证，不用一次旧登录永久授权。

## 3. Cookie、CSRF 与限速

后台静态页面和管理 API 部署在同一个 HTTPS Origin，通过反向代理转发。Cookie 名 `__Host-longju_admin`，Secure、HttpOnly、SameSite=Lax、Path=/，不设置 Domain。完整会话绝对有效期 8 小时、空闲过期 30 分钟；last_seen 最多每 60 秒更新一次以控制写入量。重新登录和第二因素通过后更换随机令牌，防止会话固定。

所有 Cookie 认证写请求，包括登录、激活、退出，要求同源 Origin 检查与服务端预会话/正式会话绑定的 CSRF Token。前端从 csrf 接口取得令牌并放入 `X-CSRF-Token`；只靠 SameSite 或 CORS 不能替代 CSRF。默认不开放跨域带凭据请求。

近期重新验证窗口为 5 分钟，与会话存活分开。密码/角色/范围/账号状态变更递增 auth_epoch、撤销相应会话；管理员停用与成员停用分别处理。

初始限速：登录失败按账号每 15 分钟最多 5 次，并叠加 IP 每 15 分钟 30 次；TOTP 每挑战最多 5 次；名录每主体每分钟 30 次；普通写操作每主体每分钟 30 次；签到工作人员每分钟 120 次；导出每主体每小时 5 次，最多 1 个生成任务。返回 429 与 Retry-After；阈值可配置并按联调流量修正，不当作容量保证。数据库原子窗口计数支持初期单/多实例，来源 IP 只信任已配置反向代理，不能信任任意 X-Forwarded-For。

## 6. 环境与运维方案

开发通过容器启动 MySQL 8.4 与本地 S3 兼容存储，用明确的测试账号与固定虚构数据；微信适配器在本地可用测试替身，配置必须显式标 dev，生产拒绝 mock 登录。测试环境接真实测试 AppID、存储和 HTTPS，用于小程序联调。生产不得复制测试管理员密码或开发引导凭证。

一期试运营部署建议沿用一台 2–4 vCPU / 4–8GB 应用机 + 托管 MySQL + 私有对象存储，单地域。具体云厂商与预算在准备部署时再由用户决定，此决定不会改变接口、数据模型或阻碍编码。服务名、桶名和域名全部通过配置注入，不在代码中绑定厂商地址。

配置分为普通参数和秘密：数据库连接、会话时长、任务并发、文件限额、业务域名为普通参数；数据库密码、微信 secret、对象存储凭据、电话/TOTP加密密钥和HMAC密钥放秘密配置。不同用途、不同环境分钥；启动检查缺失项，错误只显示配置名，不能打印值。资产/电话保存 key_version 支持滚动换钥；旧钥保留至对应数据迁移完成。

数据库私网；应用只有业务所需数据库权限，迁移使用独立账号；维护/恢复账号不用作日常连接。日志与监控包含 requestId、脱敏主体、耗时、状态、任务失败、连接池占用、备份失败及待注销超期；不记录请求体、完整查询票据或完整手机号。健康探针区分存活与就绪，业务就绪依赖数据库，不能把不可用实例继续接入流量。

CI 在合并前执行前端类型检查/构建、后端测试、MySQL真实迁移和接口契约检查，产出不可变镜像与静态构建。Flyway 迁移在发布流程单独执行，应用实例不竞争执行迁移；结构优先新增兼容，破坏性变更拆分发布。回滚切回上一镜像；不得自动执行有数据损失的数据库降级。

单实例维护窗口允许短暂停机的部署建议应在上线前确认；如需单机故障不中断，增加负载均衡与双实例，数据库会话、共享限速及任务租约已按多实例正确性设计。所有实例停止接入新请求后等待正在执行的事务完成，再退出；未完成任务依租约恢复。
