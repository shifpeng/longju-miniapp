# 活动结束后的图文回顾

本轮交付范围：小程序详情、相册与照片浏览的设计原型，以及后台管理需求。仓库目前为设计与架构资料，尚未实现真实上传、存储或发布服务。

## 小程序呈现

- 活动结束后保留名称、时间和地点，停止报名；有已发布回顾时展示回顾标题、正文、照片缩略图、图片数量及整理人。
- 点击缩略图打开对应大图，保持照片比例；支持上一张、下一张、序号和返回相册。正式开发采用微信图片预览能力支持滑动、缩放；Figma 通过按钮演示切图。
- 完整相册按管理员设置的顺序展示。照片说明可选；缺失说明不占位。计数来自已发布且可用的图片，不能包含上传中、失败或已移除的图片。
- 无已发布回顾时显示“精彩回顾整理中”，不展示空相册入口。发布纯文字回顾时隐藏图片区；只发布照片时隐藏空正文段落。
- 已结束列表可根据是否有已发布回顾显示“查看回顾”或“查看活动”。详情底部为“查看相册 / 更多活动”，不再提供报名。
- 当前原型使用既有西安城墙、鸣沙山和驼队素材示意相册，明确标注非活动实拍；真实照片由管理员提供。

## 后台入口与操作

入口：活动管理 → 已结束活动 → 活动回顾。活动运营人员仅管理权限范围内的活动。

| 区域 | 内容和行为 |
| --- | --- |
| 活动摘要 | 名称、结束时间、地点、回顾状态 |
| 图文编辑 | 回顾标题、摘要、正文；照片说明可选 |
| 图片管理 | 批量上传、逐张进度、失败重试、删除草稿图片、拖动排序、选择相册封面 |
| 发布范围 | 沿用活动可见范围，不自动扩大到公开；成员照片按该范围访问 |
| 预览 | 查看小程序的详情、相册和大图顺序 |
| 操作区 | 保存草稿、发布回顾；已发布后可编辑并发布更新，或撤下回顾 |

一期建议每次活动最多 30 张图片，单张不超过 10 MB，支持 JPEG、PNG、WebP；后台显示限制并逐张校验。服务端验证真实类型，生成缩略图和大图版本。视频和附件作为后续扩展，不混入本轮照片流程。

## 发布规则

1. 活动必须已结束才可公开回顾。至少有一段有效文字或一张上传成功且处理完成的图片。
2. 上传中或失败的图片必须重试成功或从待发布内容中移除；上传成功不等于已发布。
3. 首次保存草稿时，小程序仍显示“整理中”。发布后一次性切换到完整版本，避免正文、封面和照片数量不一致。
4. 已发布内容继续编辑时生成独立草稿；保存草稿不影响线上旧版本。发布更新成功后整体替换，失败保留线上旧版本与草稿。
5. 封面默认第一张有效照片，也可另选；删除当前封面时必须重新指定或回退到第一张。无照片时不保留失效封面。
6. 撤下后小程序回到“整理中”，后台保留内容和发布记录。原活动封面独立保存，不因选择相册封面而被覆盖。
7. 记录编辑人、发布时间、版本及撤下操作；多人编辑采用版本校验，提示冲突并保留当前未提交内容。

## 开发对应

- `activity_recap`：活动 ID、草稿内容、已发布版本 ID、发布状态、可见范围、更新时间。
- `activity_recap_version`：不可变的发布内容快照、标题正文、发布人、发布时间。
- `activity_recap_media`：版本/草稿 ID、媒体 ID、排序、说明；封面引用有效媒体 ID。
- 复用 `media_asset`，上传使用受限凭证。草稿媒体不得通过成员接口暴露；发布后按活动的可见范围返回可访问图片。
- 管理端提供读取、保存草稿、排序、发布更新和撤下接口；小程序只读取已发布版本。回顾写操作不改变活动报名和签到记录。

验收应覆盖：未上传、上传失败、图片处理中、排序和封面变更、纯文字、纯图片、草稿隔离、发布失败、撤下与权限范围；大图打开序号应与缩略图一致。
