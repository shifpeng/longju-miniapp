## 申请提示“个人信息保护指引尚未配置，请刷新后重试”

此提示来自API的`MembershipApplicationServiceImpl.validatePrivacyNotice`：运行配置`longju.privacy.notice-version`为空，而小程序已携带已发布指引版本和阅读确认。当前小程序版本为`1.0`；刷新页面不会改变API的运行配置。

应在API实际加载的配置中，将版本作为字符串与小程序保持一致，合并到已有`longju`配置下，避免重复顶层键：

```yaml
longju:
  privacy:
    notice-version: '1.0'
```

也可在既有Java应用启动命令的JAR路径之后追加`--longju.privacy.notice-version=1.0`。如果实际加载的是仓库的生产配置模板，可以在API进程环境中设置`LONGJU_PRIVACY_NOTICE_VERSION=1.0`，模板通过占位符读取该值。宝塔启动不会自动读取systemd的`production.env`，本机也不会自动读取`.env`；只改示例文件或未被进程加载的配置不会生效。

该属性在服务构造时读取，修改后需要重启对应API进程。V25的申请修订字段需已按部署流程安装，不能通过小程序不传隐私版本/确认值来绕过配置差异。

2026-10-28用户授权直接修改后，已补齐本地`longju-api/config/application-server.yaml`中的版本`'1.0'`，生产模板默认值同步为`1.0`；其余配置和文件权限保持不变。该私有文件原部署目标为`/www/server/longju/application-server.yaml`，仍需安全替换到服务器并重启对应API；本轮没有连接或修改远程服务器，没有执行迁移或重启，线上闭环尚待验证。

## 微信公众平台配置

仍需在小程序后台「设置/服务内容声明」或当前版本对应的隐私设置中配置「用户隐私保护指引」，逐项按实际上线功能申报信息类型及用途。至少核对微信登录、手工填写的姓名/联系电话/家乡/现居/行业/简介、活动报名与签到、反馈，以及用户点击扫码签到时的相机使用说明。代码页提供 `wx.getPrivacySetting` 状态读取和 `wx.openPrivacyContract` 入口；开发者工具和真机应确认它显示已发布的平台指引。

活动回顾图片由运营人员上传。运营流程须确保发布前已完成必要告知/授权，并提供处理照片异议的真实联系渠道。代码中的隐私页面不能代替后台运营取得照片授权。

## 功能缺口与可选审计

- **资料保存：**小程序现改用 `PUT /me/profile`，API 保留 PATCH 并新增相同校验、If-Match、鉴权的 PUT 路由；需与API一起部署才生效。
- **阅读确认记录：**申请表单独要求“我已阅读并知悉”，与加入须知同意分开。申请提交传入版本，服务端核对 `LONGJU_PRIVACY_NOTICE_VERSION` 并在不可变申请修订中记录版本和服务端时间。V25迁移需协调生产Flyway历史后应用。
- **一年日志期限：**应用Logback日志、Tomcat访问日志、Nginx访问日志、journald和数据库audit_log均已有一年配置。数据库audit_log清理任务目前默认关闭，排查期保留全部数据；确需启用时才会删除超过一年的记录。journald配置片段为主机级，会影响其他服务，安装前需检查磁盘容量和现有策略；生产主机尚未安装/验证这些配置。V26为audit_log新增清理索引。
- 生产环境协议版本必须与 API 的 `agreement-version` 配置一致；成员加入须知仍在 `src/config/runtime.ts`，需由运营确认正式文本和版本。

## 提审验收

1. 核实 `src/config/privacy.ts` 中的发布信息与生产 API、COS、账号清理配置一致。
2. 将同一信息配置到微信公众平台的用户隐私保护指引；开发者工具验证 `wx.getPrivacySetting` 的名称和状态，点链接能打开平台指引。
3. 检查游客登录前、申请提交前、活动报名、反馈联系开关、名录资料展示设置和扫码签到的就近告知；分别测试拒绝平台隐私授权时公开浏览仍可用、相应隐私操作不执行。
4. 测试名录资料展示开关确实保存并在重新进入后保持，名录和详情响应始终没有电话字段，申请同意版本与后台配置一致，注销提示与实际异步清理一致。
5. `npm run check`、`WECHAT_COMPILER_DIR=/Applications/wechatwebdevtools.app/Contents/Resources/app.asar.unpacked/node_modules/wcc-exec npm run check:native`，再用目标 AppID 真机预览/上传并完成平台审核检查。
